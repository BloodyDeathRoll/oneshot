- **0.4.0** — 2026-10-05 — Approved by Shahar in session (2026-10-05): "We build a demo to sell to a client. If we succeed and the client wants a CMS, THEN you implement a CMS. NOT BEFORE. Change the workflow to reflect that." Two invocations: **station 6 Preview** (from `passed`: static build of `final/` to `<brand>.os1.workers.dev` with Wrangler, noindex / robots `Disallow` / no sitemap, verified 200s and live HTML byte-identical to the local build; no CMS, tenant, owner login, domain or `deploy.json`; ledger `previewed`) and **station 8 Deliver** (only from `product_chosen`, after `outcome:sale`: the adapter for the mode the client chose; ledger `delivered`, self-hosted then `handoff_verified → access_revoked`). - **tools.md 0.3.0** — 2026-10-05 — Same change: a station-6 Preview section (build, `wrangler deploy`, verify); the adapters are station 8 only; `attach_domain` keyed to `product_chosen`.
- **0.5.0** — 2026-10-05 — Approved by Shahar in session (2026-10-05): "We need to set up tests post CMS build to make sure everything is running smoothly" — both an acceptance suite at delivery and after any CMS upgrade, and the same smoke checks on a schedule. Station 8 gains an eighth step, `check` (after `verify`): `node tools/site-check.mjs <slug> --full`, full report in `sites/<slug>/site-check.json`, summary in `deploy.json`; never continue past a failed `check`. `deploy/managed/deploy.mjs` 0.2.0: `verify`'s owner path moved to `deploy/managed/lib/cms.mjs` (shared with the suite), restores the edit even when it never reached the live site, also proves anonymous **writes** are refused; the parity normaliser (`deploy/managed/lib/parity.mjs`) strips the whole `<slug>-<sha256:8>-` prefix (was `img-`/`vid-` only: a false diff for files named otherwise, e.g. `gs-*.mp4`).
- **tools.md 0.4.0** — 2026-10-05 — Same change: the `check` row in the adapter tables, the `tools/site-check.mjs` section (smoke / acceptance / full, what each checks), and the scheduled monitor (`.github/workflows/site-monitor.yml`, every 6 h, smoke only; a failed run is the alert).
